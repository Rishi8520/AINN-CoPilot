Request Lifecycle — Step by Step

1
Operator types a query in the browser at localhost:8501. Streamlit UI (ainn-ui container) receives it and opens a streaming HTTP POST to the agent at ainn-agent:9090 inside the Docker network.
2
OPEA Agent receives the query and starts the ReAct reasoning loop. It reads ainn_tools.yaml (mounted volume) to know what tools exist. It then calls the vLLM endpoint on Member 2's machine to decide: which tool should I call first?
3
If the LLM decides to retrieve knowledge, the agent calls call_rag(query) in tools.py. This hits rag:7001/v1/retrievaltool/json → TEI Embedding → TEI Reranker → Redis VectorDB. All inside Docker on machine 3.
4
The agent uses the LLM on Member 2's machine (vllm:8080) repeatedly throughout the ReAct loop — to think, to form tool arguments, and to synthesise the final answer. All LLM calls cross the LAN.
5
If the LLM decides to run a simulation, the agent calls call_simulation(scenario, ue_count). This sends a POST to Member 1's FastAPI wrapper at M1_IP:8888/simulate over the LAN (via Windows portproxy from WSL).
6
Simu5G runs the OMNeT++ scenario in WSL on Member 1's machine and returns JSON KPIs: throughput, latency, SINR, packet loss, handover count. The agent receives this as a tool observation.
7
The agent may call multiple tools in sequence — simulate first, then RAG to back the diagnosis with standards. Each tool call is another LLM round-trip to Member 2. The loop continues until the LLM outputs a final answer.
8
The final answer streams back to the UI via SSE (Server-Sent Events). The Streamlit UI shows tool call indicators (🔬 Running Simu5G...) in real time, then renders the complete diagnosis with citations.
Machine 3 containers (Docker) — UI, Agent, RAG stack, Redis
Member 1 (WSL) — Simu5G + FastAPI, no Docker needed
Member 2 (bare) — vLLM server, RTX 5070 Ti GPU
